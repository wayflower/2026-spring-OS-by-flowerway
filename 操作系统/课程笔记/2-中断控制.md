# 💻 操作系统运行环境与运行机制 (OS Execution Environment & Mechanism)

## 零、 核心设计哲学

- **机制与策略分离原则 (Separation of Mechanism and Policy)**：
    - 机制（硬件/OS底层提供）：如中断机制、特权级切换。
    - 策略（OS高层决定）：如调度算法选哪个进程运行。
- **ECF (Exceptional Control Flow，异常控制流)**：是理解应用程序与OS交互、并发、软件异常的**核心钥匙**。

---

## 一、 处理器状态与特权级

硬件机制将操作系统与用户程序隔离，其核心是**处理器特权级别**。通过程序状态字（PSW）中的特定位来区分。

### 1. 体系结构对比

- **x86 架构**：支持4个特权环（R0 ~ R3）。从 R0（最高权限）到 R3（最低权限）。
    - **Linux 实际使用**：通常只使用 R0（内核态 / Supervisor mode）和 R3（用户态 / User mode）。
- **RISC-V 架构**：三种特权模式 。
    - `M` (Machine, 机器模式) - 级别3
    - `S` (Supervisor, 监管模式) - 级别1
    - `U` (User, 用户模式) - 级别0

### 2. 状态转换

- **用户态 ➔ 内核态**：**唯一途径**是中断/异常/陷入机制 (Trap)。
- **内核态 ➔ 用户态**：通过设置程序状态字 (PSW——RISCV的状态字) 或专用返回指令实现。
- **陷入指令 (Trap Instruction)**：也称**访管指令**，是用户请求OS服务的接口（如 `int`, `trap`, `syscall`, `ecall` ——这两条是用来系统调用的，前者为x86，后者为RISCV/xv6）。

## 二、 中断与异常机制 (Interrupts & Exceptions)

操作系统是由**中断/异常/事件驱动**的：处理中断请求；捕获用户程序提出的服务请求；防止用户程序的破坏性活动。

### 1. 事件的分类 (🔥 绝对高频考点)

| 类别 | 英文名称 | 原因 | 异步/同步 | 返回行为 |
| --- | --- | --- | --- | --- |
| **中断 (外中断)** | Interrupt | 外部I/O设备、时钟、硬件故障 | **异步** | 总是返回到**下一条**指令 |
| **陷入 (陷阱)** | Trap | 系统调用 (Syscall)、断点等有意识的安排 | **同步** | 返回到**下一条**指令 |
| **故障** | Fault | 缺页异常 (Page fault)、保护性错误等**可恢复**错误 | **同步** | 返回到**当前指令 (重新执行)** |
| **终止** | Abort | 硬件损坏等**不可恢复**错误 | **同步** | **不会返回**，直接终止程序 |

### 2. 软硬件的明确分工

- **硬件负责 (中断响应)**：
    - x86：
        - 在每条指令执行周期最后扫描中断寄存器，检查是否有中断信号。
        - 发现并接收中断。
        - 切换处理器特权态（用户态 -> 内核态）。
        - **保存现场 (压栈)**：保存 PC、PSW（EFLAGS） 等核心寄存器到系统栈。如果是异常，还可能压入错误码 (Error Code)。
        - 硬件通过查询**中断向量（保存中断处理程序入口地址+程序运行所需的处理机状态字）表 / 中断描述符表 (IDT)**，将PC指向中断处理程序入口。
    - RISCV：
        - 硬件把旧 PC 存入 `sepc`，然后把 `stvec` 里的地址直接丢给真实的 PC。
- **软件负责 (中断处理)**：
    - 进一步保存通用寄存器等现场信息 (如 `SAVE_ALL` 宏)
        - 在RISCV（xv6）中：若为用户态触发中断，则系统会执行`trampoline.S`，将其余的寄存器值存在`proc`结构体的`trapframe`中。
        - 若为内核态时再次引发中断，此时`stvec`的内容已被`usertrap()`改为了`kernelvec.S`，因此会在内核栈上保存其余寄存器。
    - 分析具体原因，执行对应设备的逻辑或错误恢复。
    - 恢复现场（除了PSW和PC以外的寄存器）。
    - 决定是否进入调度，如果否，直接执行`iret`指令恢复运行。
- **硬件负责（最终恢复）**：
    - 恢复PSW和PC，根据PSW，将cpu调整回用户态。
    - 根据PC开始下一个指令周期。

### 3. IA-32 (x86) 中断实现细节 (🔥 考点)

- **x86处理器的基本概念**：
    - 中断：由硬件引发、异步、分为可中断不可中断
    - 异常：由指令执行引发，对于某些异常，CPU会在**执行异常处理程序之前**产生硬件出错码，并压入内核态堆栈。
    - 系统调用：异常的一种，用户态到系统态唯一入口
- **实模式**：由**PIC**转换中断信号为**中断向量**，使用**中断向量表**。
$入口地址 = 段地址 << 4 + 偏移地址$，
不支持状态切换（因此中断处理与一般的过程调用相似）。
- **保护模式**：使用**中断描述符表 (IDT)**，通过 IDTR 寄存器定位 。包含多种门 (Gate)：
    - **任务门**：中断发生时，将取代当前进程的运行进程TSS选择符存放其中。
    - **中断门 (Interrupt Gate)**：进入后系统会**自动禁止中断**（清空 IF 位）。
    - **陷阱门 (Trap Gate)**：进入后系统**不会**自动关中断。*🔥 考点：这是中断门和陷阱门的核心区别！系统调用 (int 0x80) 使用的是陷阱门 ！*
    - **调用门**。
- **中断向量/中断向量表**：
    - “中断向量号“是一个数值，用以索引
    - “中断向量”是一个内存单元，为中断向量表的条目，存放中断处理程序入口地址和程序运行所需的处理机状态字
    - 这两个概念只在IA32的实模式下使用，不支持权限改变
- **中断描述符/中断描述符表**：
    - 确定中断或异常的向量i（中断向量号）
    - IDTR寄存器存放IDT表，得到中断描述符
    - GDTR获得GDT地址，结合中断描述符的段选择符和段内偏移量，找到入口程序

## 三、 系统调用 (System Call)

### 1. 基本概念

- **系统调用与 API 的区别 (🔥 经典问题)**：
    - 系统调用是 OS 提供的**唯一**内核接口，执行会触发态的切换（陷入内核）。
    - C 库函数 / API 是工作在**用户态**的函数库，它们内部可能会封装并触发系统调用（如 `printf` 内部触发 `write`），也可能完全不涉及系统调用（如 `strlen`、`abs`）。
- **机制与策略**：提供系统调用的陷入门是机制，而各个具体的系统调用函数（如 `sys_write`）的实现逻辑是策略。

### 2. x86 系统调用完整执行流程 (`int 0x80`)

1. **参数传递**：用户程序将参数放入通用寄存器。`eax` 存**系统调用号**，`ebx, ecx, edx, esi, edi` 存**参数** (最多6个) ，或者在内存中专门开辟堆栈区用于传递。
2. **触发陷入**：执行 `int $0x80`。
3. **硬件响应**：查 IDT 表的 128 (0x80) 号门（陷阱门，DPL=3允许用户态调用）。特权级切换，**切换栈**（用户栈换为内核栈），硬件自动将 用户 `SS`、`ESP`、`EFLAGS`、`CS`、`EIP` 压入内核栈。
4. **软件总入口**：跳转到 `system_call`。执行 `SAVE_ALL`（压入其他寄存器如 ds, es, eax 等）。
5. **查表分派**：检查 `eax` 中的调用号是否合法，查 `sys_call_table`，跳转到对应的内核处理函数 (如 `sys_write`)。
6. **返回过程**：内核函数执行完毕，结果存入 `eax` 。进入 `ret_from_sys_call`，检查是否需要重新调度 (`need_resched`) 或处理信号。
7. **恢复用户态**：执行 `RESTORE_ALL` 和中断返回指令，弹栈恢复寄存器，回到用户空间。

### 3. RISCV上执行系统调用

- 约定:遵循标准的 RISC-V ABI(Application Binary
Interface).
- 系统调⽤号:通过寄存器 a7 传递.
- 参数:前六个参数通过寄存器 a0 到 a5 传递.
- 返回值:通过寄存器 a0 返回(对于 64 位或更宽的返回
值,可能还使⽤ a1).

## 四、 XV6 (RISC-V) 代码级硬核细节 (🔥 必考)

在 RISC-V 中，处理异常/中断的硬件动作非常精简，大部分工作依赖控制寄存器和软件（`trampoline.S`）配合完成：

### 1. 核心控制寄存器 (Control Registers)

- `stvec` (Supervisor Trap Vector Base Address Register)：保存陷入处理程序（如 `trampoline` 或 `kernelvec`）的**入口基地址** 。
- `sepc` (Supervisor Exception Program Counter)：发生陷入时，硬件自动将**被中断指令的 PC 值**（即断点）保存在此，用于后续恢复 。
- `scause` (Supervisor Cause Register)：记录**发生陷阱的原因**（是中断、缺页、还是 ecall），OS 读取它来进行分发 。
- `sstatus` (Supervisor Status Register)：包含特权级状态、中断使能标志（如 SIE 位）。硬件会在陷入时自动更新此寄存器 。

### 2. 上下文保存 (TRAPFRAME)

XV6 发生中断时，在 `trampoline.S` 中，代码会将所有 32 个通用寄存器（包括 `sp`, `ra`, `a0~a7` 等）全部保存到该进程专用的 `TRAPFRAME` 结构体内存中 。这与 x86 硬件自动压一部分入栈的行为有很大区别。

### 3. 源码部分

**1. 特权模式及启动转换 (Boot)**

- **xv6-riscv 的特权模式**：共有三种，分别是 **机器模式 (M 模式)**、**监管模式 (S 模式)** 和 **用户模式 (U 模式)** 。
- **启动阶段转换过程**：
    - **M 模式 ➔ S 模式**：计算机加电后首先进入 **M 模式** 。在 `start.c` 的 `start()` 函数中，硬件通过设置 `mstatus` 寄存器并执行 `mret` 指令，使 CPU 从 **M 模式转换到 S 模式**，随后进入 `main.c` 执行 。
    - **S 模式 ➔ U 模式**：在 `main.c` 完成系统初始化并创建第一个进程后，通过执行 `usertrapret`（最终在 `trampoline.S` 中执行 `sret` 指令），CPU 从 **S 模式转换到 U 模式**，开始运行用户程序

**2. 系统调用寄存器传递 (Syscall)**
在 xv6-riscv 中进行系统调用时，参数和信息的传递遵循 RISC-V 调用约定：

- **系统调用号**：通过 **`a7`** 寄存器传递 。
    - **参数**：通过 **`a0`, `a1`, `a2`, `a3`, `a4`, `a5`** 寄存器传递（最多支持 6 个参数）
    - **返回值**：处理结果最后通过 **`a0`** 寄存器返回给用户程序 。

**3. 上下文切换保存的寄存器 (Trap)**
根据 `trampoline.S` 和 `kernelvec.S` 的定义，当发生 Trap（如用户态进入内核态）时，需要保存进程的**全套通用寄存器**以确保现场可恢复 ：

- **具体寄存器包括**：`ra` (返回地址)、`sp` (栈指针)、`gp` (全局指针)、`tp` (线程指针)、`t0-t6` (临时寄存器)、`a0-a7` (参数/返回值寄存器)、`s0-s11` (保存寄存器) 。
- **保存位置**：从用户态进入内核时，保存到该进程 PCB 的 **`trapframe`** 中；从内核态再次触发中断时，则压入 **内核栈** 。

**4. 关键控制寄存器作用 (Trap)**
阅读 xv6-book 4.1 节及 `trap.c` 代码，这些寄存器在 Trap 处理中起核心作用 ：

- **`stvec` (Supervisor Trap Vector Base Address Register)**：保存中断处理程序的**入口基地址**。发生 Trap 时，硬件自动将 PC 指向此处 。
- **`sepc` (Supervisor Exception Program Counter)**：当发生 Trap 时，硬件自动将**被打断的指令地址**保存在此处，用于后续恢复执行 。
- **`scause` (Supervisor Cause Register)**：记录**发生 Trap 的原因**（例如是系统调用、缺页异常还是外部硬件中断） 。
- **`sstatus` (Supervisor Status Register)**：监控和控制当前 **处理器状态**，包括中断使能标志（SIE）以及之前的特权模式（SPP） 。

**5. 中断处理函数流程 (Interrupt)**

- **`devintr` (设备中断分发)**：
    - 首先读取 `scause` 寄存器确认是否为外部硬件中断 。
    - 调用 `plic_claim()` 获取当前发出中断请求的设备 ID 。
    - 根据设备 ID 跳转到相应的处理函数（如 `uartintr`） 。
    - 处理完成后调用 `plic_complete()` 告知 PLIC 处理完毕 。
- **`uartintr` (串口中断处理)**：
    - 读取 UART 的状态寄存器，判断是接收到了数据还是发送缓冲区已空 。
    - 如果有输入数据，则读取字符并将其送入控制台缓冲区（`consoleintr`） 。
    - 如果发送缓冲区空闲，则从输出环形缓冲区取下一个字符并发送 。
- **`devintr` 调用 `uartintr` 的判断条件**：
    1. 发生的是**外部硬件中断**（`scause` 显示为 Supervisor external interrupt） 。
    2. 通过 **PLIC 识别出的设备 ID** 与 **UART0_IRQ**（通常为 10）匹配 。

## 五、概念对比

| **概念维度** | **Intel X86 (IA-32 / x86-64)** | **RISC-V (以 xv6 实验环境为例)** | **核心机制与区别解析** |
| --- | --- | --- | --- |
| **特权级别 (Privilege Levels)** | **4 Ring 架构** (Ring 0 ~ Ring 3)。
OS常用 Ring 0 (内核) 和 Ring 3 (用户)。  | **3 Mode 架构** (M, S, U)。
M是机器态(最高权，常驻固件)，OS内核跑在 S态，用户跑在 U态。  | RISC-V 引入 M 态是为了支持底层的硬件固件(SBI)和虚拟化基础，而 OS 通常只拥有 S 态权限。 |
| **页表基址寄存器** | **CR3** (Control Register 3) | **SATP** (Supervisor Address Translation and Protection) | **切换进程虚存的关键**。发生进程调度时，OS 必须将新进程的页表根目录物理地址写入该寄存器。SATP 还能配置分页模式 (Sv39等)。 |
| **中断向量表/描述符表** | **IDT** (Interrupt Descriptor Table)，通过 **IDTR** 寄存器定位。  | 统跳入口 **stvec**，不查硬件表。  | **设计哲学差异**：X86(CISC) 硬件极其勤快，硬件根据中断号查 IDT 表直接跳到对应的服务程序。RISC-V(RISC) 硬件极简，所有陷阱统一跳到 `stvec` 指向的同一地址，由软件去读 `scause` 进行查表分类。 |
| **中断返回地址保存** | 硬件自动把断点 (EIP/CS) **压入内核栈** (Memory)。  | 硬件自动把断点存入 **`sepc` 内部寄存器**。  | RISC-V 为了提高速度，陷入内核的一瞬间**绝不访问内存**，全靠内部寄存器留证。 |
| **系统调用指令** | 早期：`int 0x80`
现代：`sysenter` / `syscall`  | `ecall` (Environment Call)  | `ecall` 会触发同步异常，硬件将 `scause` 设为对应的值（如来自U mode的ecall为8）。 |
| **系统调用传参方式** | `eax` 传调用号。
`ebx`, `ecx`, `edx`, `esi`, `edi` 传参数。  | `a7` 传调用号。
`a0 ~ a5` 传参数。 | 原理相同，都是因为陷入指令无法携带复杂参数，所以借用**通用寄存器**作为跳板。  |
| **陷阱门 vs 中断门** | IDT 中明确区分 Interrupt Gate (自动关中断) 和 Trap Gate (不关中断)。  | 硬件不分门类。陷入内核瞬间，硬件自动清除 `sstatus` 中的 `SIE` 位（**统一自动关中断**）。 | RISC-V 交给内核软件自己决定何时重新开启中断，硬件行为更加统一。 |
| **上下文保护 (Context Save)** | **软硬混打**：硬件自动压入SS, ESP, EFLAGS, CS, EIP。剩下的由汇编 `SAVE_ALL` 压栈。  | **纯软件干活**：汇编代码在 `trampoline.S` 中手动将 32 个寄存器保存到内存的 Trapframe 结构中。  | X86 有硬件上下文压栈支持；RISC-V 坚持 RISC 理念，让汇编代码通过普通的 `sd` 指令完成所有的现场保存。 |

### **中断发生后OS底层工作步骤**

1. 硬件压栈：程序计数器等
2. 硬件从中断向量装入新的程序计数器等
3. 汇编语言过程保存寄存器值
4. 汇编语言过程设置新的堆栈
5. C语言中断服务程序运行（例：读并缓冲输入）
6. 进程调度程序决定下一个将运行的进程
7. C语言过程返回至汇编代码
8. 汇编语言过程开始运行新的当前进程
1. 硬件压栈：程序计数器等
2. 硬件从中断向量装入新的程序计数器等
3. 汇编语言过程保存寄存器值
4. 汇编语言过程设置新的堆栈
5. C语言中断服务程序运行（例：读并缓冲输入）
6. 进程调度程序决定下一个将运行的进程
7. C语言过程返回至汇编代码
8. 汇编语言过程开始运行新的当前进程
